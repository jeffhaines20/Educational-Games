# The Cardiac Case Files — Design & Developer Guide

This file is the contract between everyone who builds the game: the engine, the user
interface, the ECG renderer and the case content. If code and this document disagree,
fix one of them; don't let them drift.

---

## 1. Goals and hard constraints

**What it is.** A case-based study game for a physical therapist assistant (PTA) course on
cardiovascular pathology. The player is the newest PTA at a fictional rehab centre. Each
*case file* is a patient: referral, history, medications, vital signs, examination findings
and test results. The player works the case step by step — recognising what is going on,
choosing tests, interpreting ECG strips and numbers, and deciding how to help the patient
safely (and when to stop and get the supervising PT, nurse, physician or emergency
services). Every answer is explained.

**Source material.** Two lecture decks in the repository root:

* Lecture 1 — `Cardiovascular system Pathology (1).pptx` (L1): anatomy and physiology,
  conduction, cardiac cycle, ECG, heart sounds, cardinal signs and symptoms, diagnostic
  tests, ten drug classes with PT implications, procedures.
* Lecture 2 — `Patho cardio conditions 2 (1).pptx` (L2): aneurysm, angina, atherosclerosis,
  CAD, hypertension, MI, CHF, pulmonary edema, cardiomyopathy, PVD, Buerger's disease,
  diabetic angiopathy, Raynaud's, DVT, PE, chronic venous insufficiency, cor pulmonale.

`docs/SOURCE-NOTES.md` is the digest (with slide numbers) that content is written from.
Cases cite their sources ("L2 s6–8 · Angina pectoris"). Where a slide is out of date or
imprecise, the game follows current practice and says so — see `docs/SOURCE-NOTES.md` §0.

**Hard constraints.**

1. **No installation, no server, no network.** Plain HTML, CSS and classic scripts (no ES
   modules, no `fetch`, no CDN). The game must work when `index.html` is opened from disk
   (`file://`), from GitHub Pages, inside an LMS iframe and as a SCORM package. Everything
   (fonts, icons, scripts) is local; the single-file build (`dist/`) inlines it all.
2. **Progress saves automatically** (browser storage, three slots), can be moved between
   computers with a save code, and syncs to the LMS in SCORM mode.
3. **Accurate and safe.** Content follows the lectures; nothing taught as correct may be
   wrong by current standards. Management answers stay within PTA scope: stop or modify the
   session, monitor, position, educate, and notify the supervising PT — or activate the
   emergency response. PTAs don't diagnose, prescribe, or change medications; questions
   ask "which condition best explains these findings?" rather than "diagnose".
4. **Accessible.** Keyboard-playable, screen-reader friendly (ECG strips have text
   descriptions), WCAG AA contrast, `prefers-reduced-motion` respected, works from 360 px
   wide phones to large monitors.
5. **Fictional patients**, a disclaimer ("for education only — not medical advice"), no
   real names or photos, and no images copied from the lecture slides (the slides' figures
   are textbook and web images; the game draws its own ECGs and diagrams).

Everything hangs off one global, `window.CCF`. Engine and UI files start with
`var CCF = (window.CCF = window.CCF || {});`; content files simply call `CCF.define…`,
which `registry.js` has already created. A content file that fails to load (missing,
or a syntax error) must not stop the game: the registry records which files ran, the
others' cases are simply absent, and the UI shows a quiet warning.
`tools/validate_content.js` fails if a `js/content/*.js` file is not referenced by
`index.html`.

## 4. Game design

### 4.1 Setting and characters

* **Riverside Heart & Vascular Center** — a fictional hospital with an outpatient clinic,
  an inpatient rehab floor, a cardiac rehab gym and a home-health team. Cases happen in all
  of these settings.
* **The player** — the newest physical therapist assistant on the team. Addressed as
  "you"; the player chooses a display name (for the save slot and certificate).
* **Dr. Maya Okafor, PT, DPT** (`okafor`) — the player's clinical instructor and the
  supervising PT. Gives the intro, gives hints ("Ask Dr. Okafor"), and appears in debriefs.
* Patients: fictional, diverse in age, sex and background; first name + last name; each case
  gives age and sex. No real people.

Tone: warm, professional, a little playful in titles ("The Snow Shoveler", "Three
Pillows") — a detective's case file, but the medicine is serious. No gore, no deaths shown;
emergencies end with the patient handed over to the emergency team.

### 4.2 Units ("case drawers") and difficulty

Six units, each a drawer of case files. All units are open from the start, so students can
work on whatever their course is covering. Inside a unit the cases go easy → medium → hard,
and **each case unlocks when the previous case in that unit is solved** (the first case of
every unit is open). `?unlock=all` (or `CCF_CONFIG.unlockAll`) opens everything.

| # | id | Title | Covers |
|---|---|---|---|
| 1 | `basics` | Heart Basics | blood flow, conduction, cardiac output, ECG basics, heart sounds, edema |
| 2 | `coronary` | Coronary Cases | angina, CAD, MI, cardiac rehab, nitrates, beta blockers, antiplatelets |
| 3 | `rhythm` | Rhythm Cases | palpitations, PVCs, atrial fibrillation, heart block, VF, digoxin |
| 4 | `pump` | Pump Failure | heart failure (left/right), pulmonary edema, cardiomyopathy, cor pulmonale |
| 5 | `pressure` | Pressure Cases | hypertension, orthostatic hypotension, aortic atherosclerosis, aneurysm |
| 6 | `vessels` | Vessel Cases | PVD/claudication/ABI, Raynaud's, Buerger's, diabetic angiopathy, CVI, DVT, PE |

Difficulty (shown on every case card as a labelled badge, never colour alone):

* **Easy** — a classic presentation; 3–4 steps; recognising the condition and the first
  safe action; drug classes are named in the medication list.
* **Medium** — 4–5 steps; combine several parts of the chart (vitals + medications + tests);
  calculations (cardiac output, ejection fraction, ABI); PT implications of medications;
  choosing the right test. Medication lists give names only (the Casebook has the classes).
* **Hard** — 5–6 steps; atypical or changing presentations (the patient gets worse during
  the session), telling look-alikes apart (PE vs MI, unstable vs stable angina), emergencies
  and priorities, several medications interacting, scoring tools (Wells).

`docs/CASE-PLAN.md` lists all 34 cases.

### 4.3 How a case plays

1. **Open the file.** The case screen shows the *case file* (left on wide screens, top on
   phones): Referral · History · Medications · Vitals · Exam · Tests, as tabs or stacked
   sections. Sealed test results show as "Not yet ordered".
2. **Work the steps.** One question at a time, on the right. A step may first reveal new
   information — an *update* ("Ten minutes into the walk, Mr. Brenner stops…") with new
   vitals and new exhibits, which are also added to the file and flagged *New*.
3. **Answer.** Correct → the step's explanation, then *Next*. Wrong → feedback on that
   specific choice, the choice is marked, and the player tries again (a *strike*). After
   `config.revealAfter` (default 2) wrong attempts on a step a *Show me the answer* button
   appears (using it counts as one more strike and solves the step with the explanation).
4. **Ask Dr. Okafor.** Each step has 1–2 hints; each hint revealed is a strike.
5. **Case closed.** A *CASE CLOSED* stamp, the stars earned, XP, any rank-up, and the
   debrief: what it was, a short summary, 3–5 take-home points, and the lecture sources.
   Buttons: *Next case* · *Back to the board* · *Replay*.

Progress inside a case is saved after every step, so a student can leave and come back to
the same step. Replaying a solved case is allowed; the best result is kept.

### 4.4 Scoring, stars, XP and ranks (implemented in `CCF.Progress`)

* **Strikes** = wrong attempts + hints used + "show me" uses, over the whole case.
* **Stars:** 0 strikes → ★★★; strikes ≤ ⌈steps ÷ 2⌉ → ★★; otherwise ★. Solving always
  earns at least one star.
* **XP:** base by difficulty (easy 10, medium 20, hard 30) × stars ÷ 3, rounded; replays
  only add the difference when they beat the best result.
* **Ranks** by total XP as a share of the maximum possible XP: Student Clinician (0),
  Rookie Investigator (10 %), Case Detective (30 %), Senior Detective (55 %),
  Chief Cardiac Detective (80 %).
* **Completion:** all cases solved → the finale dialogue and a printable certificate.

### 4.5 Other screens

* **Title** — the game's name as a case-file folder, *Begin* / *Continue as ⟨name⟩*,
  *I have a save code*, About (credits, disclaimer).
* **Save slots** — three slots (name, rank, cases solved, stars, last played); continue,
  new, delete (confirm), import a save code. Skipped in SCORM mode (one LMS profile).
* **Intro** — Dr. Okafor's welcome (story.intro), once per profile, skippable.
* **Case board** (home) — the player card (name, rank, XP bar, cases solved, stars), a
  *Continue* button for the next unsolved unlocked case, and the six drawers with their case
  cards (case number "2.3", title, patient name and age, difficulty badge, stars,
  *CASE CLOSED* stamp when solved, padlock when locked, *In progress* when part-done).
* **Casebook** — the reference library: Conditions, Concepts, Drugs and Tools (tables,
  scales and tests), searchable. Always available, also during a case (as a side panel or
  dialog that keeps the case's state). `?reference=off` hides it (for instructors who want
  closed-book play).
* **Rapid Rounds** — endless drills generated by code, no content files: *Name that rhythm*
  (an ECG strip, four choices), *Stage the pressure* (a BP reading → category),
  *Calculate the ABI* (pressures → ABI and its category), *Grade the edema* (pit depth and
  rebound time → 1+ to 4+). Each keeps a best streak; drills don't change case progress.
* **Case log** — every case with stars and dates, per-unit totals, and a printable
  progress report for instructors who don't use SCORM.
* **Settings** — sound, reduce motion, text size, rename, save code (export/import),
  credits and disclaimer.

## 5. Engine APIs

### 5.1 `CCF.config` (js/config.js)

Defaults, overridden by `window.CCF_CONFIG` (set by a page or the build), then by URL
parameters. Keys:

| Key | Default | Meaning |
|---|---|---|
| `title` | `"The Cardiac Case Files"` | |
| `version` | `"1.0.0"` | shown in About |
| `storageKey` | `"cardiac-case-files"` | prefix for localStorage keys |
| `saveSlots` | `3` | |
| `unlockAll` | `false` | `?unlock=all` |
| `reference` | `true` | Casebook available; `?reference=off` |
| `hints` | `true` | hints available; `?hints=off` |
| `revealAfter` | `2` | wrong attempts on a step before *Show me the answer* appears |
| `scorm` | `{ enabled: true, completionThreshold: 1.0, allowImport: false }` | |
| `scormRequired` | `false` | true in the SCORM build: warn if no LMS API is found |

The UI also honours `?sound=off` and `?motion=reduce`.

### 5.2 `CCF.Save` (js/engine/save.js)

Adapt Pyromancer's `SS.Save` (slots, storage-failure handling, cross-tab merge, save
codes, SCORM suspend data). The profile:

```js
{
  v: 1, id, name, createdAt, updatedAt,
  settings: { sound: true, reduceMotion: false, textSize: "md" },
  seen: { "intro": true, ... },                 // one-time screens
  cases: {
    "coronary-snow-shoveler": {
      solved: true, bestStars: 3, bestStrikes: 0, xp: 10,
      plays: 2, firstSolvedAt: ISO, lastPlayedAt: ISO,
      current: null | { step: 2, strikes: 1, hints: 1, answers: [...] }   // in-progress state
    }
  },
  drills: { "rhythm": { best: 7, played: 20 }, ... }
}
```

API (all return copies; all writes persist immediately; none throws on storage failure):

```js
CCF.Save.init()                       // → { mode: "local" | "scorm", storageOk, warning }
CCF.Save.isScorm()
CCF.Save.listSlots()                  // → [{ slot, empty, damaged, summary: { name, rankTitle, solved, total, stars, updatedAt } }]
CCF.Save.newProfile(slot, name)       // → profile (becomes current)
CCF.Save.load(slot)                   // → profile | null
CCF.Save.current()  / currentSlot() / lastSlot()
CCF.Save.deleteSlot(slot)
CCF.Save.rename(name)
CCF.Save.settings() / setSetting(key, value)
CCF.Save.hasSeen(key) / markSeen(key)
CCF.Save.caseRecord(caseId)           // → record | null
CCF.Save.saveCaseProgress(caseId, current)   // current: { step, strikes, hints, answers } (UI's payload; keep it < 2 KB)
CCF.Save.clearCaseProgress(caseId)
CCF.Save.recordSolve(caseId, { strikes, hints, stepCount })
      // → { stars, firstSolve, improved, xpGained, totalXp, rankUp: { from, to } | null }
CCF.Save.recordDrill(drillId, streak)  // → { best, isBest }
CCF.Save.exportCode()                 // → "CCF1.…" text code
CCF.Save.importCode(code, slot)       // → { ok, profile } | { ok: false, error }
CCF.Save.storageWarning()             // → null | human-readable warning
CCF.Save.onChange(fn)                 // fires after any change (incl. another tab)
```

### 5.3 `CCF.Progress` (js/engine/progress.js)

```js
CCF.Progress.starsFor(strikes, stepCount)   // → 1..3
CCF.Progress.xpFor(caseDef, stars)          // → integer
CCF.Progress.maxXp()
CCF.Progress.totalXp(profile)
CCF.Progress.RANKS                          // [{ title, share }]
CCF.Progress.rankFor(xp)                    // → { index, title, minXp, nextTitle, nextXp, fraction }
CCF.Progress.isUnlocked(profile, caseId)
CCF.Progress.unitStats(profile, unitId)     // → { solved, total, stars, maxStars, inProgress }
CCF.Progress.overall(profile)               // → { solved, total, stars, maxStars, xp, complete }
CCF.Progress.nextCase(profile)              // → caseDef to continue (in progress first, then the first unlocked unsolved)
```

### 5.4 `CCF.Scorm` and the builds

As in Pyromancer: detect SCORM 2004 or 1.2, store the compressed profile in
`suspend_data`, report `score.raw` = round(100 × solved ÷ total), and completion/passed
when solved ÷ total ≥ `completionThreshold`. `tools/build.py` writes
`dist/cardiac-case-files.html` (one self-contained file) and
`dist/cardiac-case-files-scorm.zip` (SCORM 1.2; `scormRequired: true`). Option
`--reference off` bakes in closed-book mode.

## 6. Content format

All content files are classic scripts that call the registry. Text fields marked
**RichText** accept:

* a string — one paragraph; or an array of blocks (strings are paragraphs);
* block objects: `{ list: [inline…] }`, `{ olist: [inline…] }`, `{ tip: inline }`,
  `{ warn: inline }` (a red flag), `{ quote: inline, by: "…" }` (what someone said),
  `{ table: { head: [...], rows: [[...], ...] } }`;
* inline markup: `**bold**` and `*italic*`. No HTML — the renderer escapes everything.

### 6.1 Units

```js
CCF.defineUnit({
  id: "coronary", order: 2,
  title: "Coronary Cases", subtitle: "Angina, heart attack and coronary artery disease",
  icon: "heart-beats",                 // a game-icons.net name (the UI maps unknown names to a default)
  intro: RichText                      // optional, shown on the drawer
});
```

Units are defined in `registry.js` (all six) so content files only define cases and entries.

### 6.2 Cases

```js
CCF.defineCase({
  id: "coronary-snow-shoveler",        // kebab-case, starts with "<unit>-", unique
  unit: "coronary", order: 1,          // order inside the unit (1, 2, 3 … no gaps)
  difficulty: "easy",                  // "easy" | "medium" | "hard"
  title: "The Snow Shoveler",
  teaser: "Chest tightness that arrives with the snow — and leaves when he rests.",  // ≤ 100 chars, no spoilers
  patient: { name: "Harold Brenner", age: 62, sex: "M" },          // sex: "F" | "M"
  setting: "Outpatient physical therapy clinic",
  file: {
    referral: RichText,                // who sent the patient and why; the chief complaint
    history: RichText,                 // HPI, past medical, social, family (a list works well)
    medications: [                     // may be []
      { name: "Lisinopril", dose: "20 mg daily", class: "ACE inhibitor" }   // class only on easy cases
    ],
    allergies: "No known drug allergies",                               // optional
    vitals: { hr: 82, bp: "148/88", rr: 16, spo2: 97, temp: "98.4 °F", pain: "0/10" },
    exam: RichText,                    // what you observe and measure
    tests: [ Exhibit, … ]              // results available now, or sealed until ordered (§6.4)
  },
  steps: [ Step, … ],                  // 3–6 steps (§6.3)
  debrief: {
    diagnosis: "Stable angina pectoris from coronary artery disease",
    summary: RichText,                 // 2–4 sentences
    takeaways: [ "…", "…", "…" ],      // 3–5 inline strings
    sources: [ "L2 s6–8 · Angina pectoris", "L1 s59 · Nitrate agents" ]
  },
  casebook: [ "angina", "nitrates" ]   // ids of Casebook entries this case relates to
});
```

**Vitals keys** (all optional; values are numbers or short strings): `hr` (bpm), `bp`
(mmHg, "120/80"), `rr` (breaths/min), `spo2` (%), `temp`, `pain` ("3/10"), `rpe` (Borg
6–20), `weight`, `rhythm` (e.g. "irregularly irregular"), and `other: [{ label, value }]`.
The UI shows values as given, with units; it never flags vitals as abnormal (spotting that
is the player's job). Lab rows carry their own `flag`.

### 6.3 Steps

Common fields:

```js
{
  id: "s1",                            // unique inside the case
  update: {                            // optional: shown before the prompt, and added to the file
    title: "Ten minutes into the bike ride…",
    text: RichText,
    vitals: { hr: 104, bp: "158/94", rr: 22, spo2: 96 },   // the new "now" vitals (history is kept)
    exhibits: [ Exhibit, … ]           // new results, added to the file's Tests
  },
  type: "single",                      // see below
  prompt: RichText,
  hints: [ "…", "…" ],                 // 1–2, Dr. Okafor's voice; nudge, never give the answer away
  explain: RichText,                   // the teaching point shown once the step is solved
  keepOrder: false                     // true = don't shuffle the options (e.g. 1+ … 4+)
}
```

Types and their fields:

* `single` — `options: [{ text, correct?: true, why }]`, 3–5 options, exactly one correct.
  `why` is the feedback for choosing that option (for the correct one: why it's right).
* `multi` — "Select all that apply": 4–7 options, at least 2 correct and at least 1 not.
  Each option has `why`. Correct only when the selection matches exactly.
* `test` — "Which test should you ask about / would confirm this?": like `single`, and the
  correct option has `reveals: ["exhibitId", …]` — sealed exhibits that open when solved.
* `numeric` — `answer` (number), `tolerance` (absolute), `unit` (e.g. "L/min", "%",
  "points"), optional `traps: [{ value, tolerance, why }]` for predictable mistakes (e.g.
  dividing by the lower arm pressure).
* `classify` — `categories: ["Arterial", "Venous"]` (2–4), `items: [{ text, category, why? }]`
  (4–8; `category` is the index). Correct when every item is in its category.
* `order` — `items: ["first", "second", …]` (4–7) in the correct order; shown shuffled.

Options are shuffled per case (deterministically) unless `keepOrder` is set. Never use
"all of the above" / "none of the above".

### 6.4 Exhibits

Every exhibit has `id` (unique in the case), `type`, `title`, and may have `sealed: true`
(hidden until a `test` step reveals it) and `caption`.

* `ecg` — a rhythm strip drawn by `CCF.ECG` (§8): `rhythm`, `rate`, `lead`, `seconds`,
  `seed`, morphology options, optional `describe` (text alternative override).
* `labs` — `rows: [{ name, value, unit, ref, flag: "high" | "low" | null }]`, optional `note`.
* `table` — `head: [...]`, `rows: [[...], ...]`, optional `note` (ABI pressures, a session
  log, a checklist).
* `report` — `text: RichText` (echo, ultrasound, catheterization, chest X-ray, physician note).
* `note` — `text: RichText`, optional `author` (a nursing note, a patient's diary, a message).
* `diagram` — a built-in drawing: `name: "auscultation"` (a chest outline with the
  auscultation areas marked by numbers 1–5 or by name; option `labels: "numbers" | "names"`).

### 6.5 Casebook entries

```js
CCF.defineEntry({
  id: "angina", kind: "condition",     // "condition" | "concept" | "drug" | "tool"
  unit: "coronary",                    // optional, for grouping
  title: "Angina pectoris",
  aka: ["chest pain of ischemic origin"],
  summary: RichText,                   // 1–3 sentences
  sections: [ { heading: "Signs and symptoms", body: RichText }, … ],
  sources: [ "L2 s6–11" ]
});
```

### 6.6 Story

```js
CCF.defineStory({ intro: [ { speaker: "okafor" | "narrator", text: RichText }, … ],
                  finale: [ … ] });
```

### 6.7 Quality bar for every case

* Grounded in the lectures (cite the slides); anything beyond them is standard, current
  practice and explained in the step's `explain`.
* One defensible answer per `single`/`test` step. Distractors are plausible (common
  misconceptions, look-alike conditions) and each has its own `why`.
* Management questions stay within PTA scope (§1.3). "Notify the supervising PT" is right
  for new or worrying findings; "activate the emergency response / call 911" for
  emergencies (signs of MI, unstable angina, PE, ruptured aneurysm, cardiac arrest,
  stroke-like signs, acute pulmonary edema, hypertensive crisis with symptoms).
* The chart contains every fact the questions need; questions never require knowledge
  that is neither in the lecture nor explained in the case.
* Numbers are realistic (vitals, labs, ABI pressures) and internally consistent.
* Reading level: clear plain English; medical terms are welcome but explained the first
  time a case leans on them.

## 7. User interface

* **Look:** a detective's desk at night — deep slate/navy background, manila case folders
  (warm paper colour) with paper-clip and tab details, typewriter headings, a red
  *CASE CLOSED* stamp, ECG paper in pink. Body text in a clean sans-serif; vitals and labs
  in a monospace face. Three self-hosted font families at most (OFL or Apache licences).
* **Icons:** game-icons.net (CC BY 3.0, credited in About), built like Pyromancer's
  (`tools/build_icons.js` → `js/ui/icon-data.js`). Decorative icons are `aria-hidden`.
* **Answers:** large, keyboard-reachable targets; feedback in an `aria-live` region; focus
  moves sensibly (to the feedback, then *Next*); choices marked with text/icons as well as
  colour.
* **Layout:** two columns (file | steps) at ≥ 1100 px, stacked below; nothing scrolls
  sideways at 360 px; the current step is always reachable without hunting.
* **Safety of rendering:** content strings go through the RichText renderer or
  `textContent`; never raw `innerHTML` with content or player input.
* **Sound:** optional tiny Web Audio effects (a heartbeat blip, a stamp thud), off with
  `?sound=off` or in Settings.

## 8. `CCF.ECG` (js/ui/ecg.js)

```js
CCF.ECG.RHYTHMS          // [{ id, name, rateRange: [lo, hi], defaultRate, description }]
CCF.ECG.generate(spec)   // → { seconds, samples: [{ t, mv }], beats: [{ t, kind: "sinus" | "pvc" | "paced" | "escape" }], pWaves: [t…] }
CCF.ECG.render(spec, opts)   // → <figure> containing an <svg> strip (+ caption); opts: { width, compact }
CCF.ECG.describe(spec)   // → plain-English text alternative that names the features, not the diagnosis
```

Spec fields (content uses these in `ecg` exhibits):

| Field | Meaning |
|---|---|
| `rhythm` | `nsr`, `sinus-brady`, `sinus-tach`, `afib`, `aflutter`, `pvc`, `av-block-1`, `av-block-2-type1`, `av-block-2-type2`, `av-block-3`, `vtach`, `vfib`, `paced` |
| `rate` | ventricular rate in bpm (average for `afib`); ignored for `vfib` |
| `seconds` | strip length, default 6 |
| `lead` | label, default "II" |
| `seed` | integer; same spec + seed → identical strip |
| `st`, `stMm`, `stSlope` | `"elevation"` or `"depression"`, size in mm (1–4), `"downsloping"` / `"horizontal"` / `"upsloping"` |
| `tWave` | `"inverted"` |
| `qWave` | `true` = pathological Q waves |
| `qrs` | QRS width in seconds (≥ 0.12 is wide) |
| `pr` | PR interval in seconds |
| `pvc` | `{ pattern: "isolated" | "bigeminy" | "couplets" | "multifocal", count }` for `rhythm: "pvc"` |
| `conduction` | flutter ratio: 2, 3, 4 or `"variable"` |
| `atrialRate` | P-wave rate for `av-block-3` (default 80) and flutter (default 300) |

Rules: standard paper (25 mm/s, 10 mm/mV; small squares 0.04 s, large squares 0.20 s), a
mark every 3 seconds along the top, and beat placement such that a 6-second strip at rate
*R* shows `round(R ÷ 10)` QRS complexes (±1), so the 6-second counting method works.
The waveforms should look like real strips: a clear P–QRS–T for sinus rhythms; no P waves
and an irregular baseline for atrial fibrillation; sawtooth flutter waves; wide, early,
bizarre PVCs with a compensatory pause; lengthening PR with a dropped beat (Mobitz I);
constant PR with dropped beats (Mobitz II); P waves marching through independent wide
escape beats (third-degree block); chaotic waves with no QRS (VF); wide regular complexes
(VT); pacing spikes before wide complexes (paced).

## 9. Testing

* `node tools/validate_content.js` — schema and quality checks over all content; exits
  non-zero on any error. Run it after every content change.
* `node tools/test_engine.js` — engine unit tests.
* `node tools/test_ecg.js` — rhythm generator tests (rates, regularity, beat counts, determinism).
* `node tools/e2e/ui-flow.js` and `ui-robustness.js` — Playwright (Chromium is preinstalled:
  `require('playwright')` works; don't install browsers). Flow: new game → intro → board →
  solve a case with right and wrong answers and a hint → stars/XP → reload → resume a case
  mid-way → Casebook → Rapid Rounds → case log → save code export/import; responsive pass
  at 1440×900, 1024×768 and 390×844; no horizontal scroll; no console errors. Robustness:
  storage blocked, `file://`, SCORM (mock API), unlock=all, reference off, corrupt saves.
* `python3 tools/build.py` then open `dist/cardiac-case-files.html` from disk.
